1. 协议 / ALPN 探测

确认浏览器实际协商 h2，并由服务器返回请求版本。

2. 基础 GET / POST

验证普通请求与 DATA 请求体在 HTTP/2 下保持现有 handler 兼容。

3. Multiplexing 并发

同一 origin 并发发出多个延迟请求，观察 HTTP/2 多 stream 并行处理。

请求数 延迟ms

4. Burst QPS

浏览器端并发压测，输出 RPS 与 p50/p95/p99。用于快速对比，不替代 Erlang 本地 benchmark。

总请求 并发

5. 大响应吞吐

下载动态生成的二进制响应，检查 DATA frame 分片与发送 flow-control。

大小 MiB

6. 大请求体 / Echo

上传二进制 body 并回显，验证 DATA 接收、body 上限和响应发送。

大小 MiB

7. 流式 DATA

读取 /stream 的 ReadableStream，观察分块到达时间，验证 HTTP/2 streaming。

8. RST_STREAM / Abort

客户端取消一个延迟 stream 后立即发新请求，验证取消不会破坏整个 H2 connection。

9. Compression

请求可压缩响应并显示 Content-Encoding、Vary 与最终正文长度。
